# 快速修復 Linting 問題

自動修復代碼質量問題，包含自動修復、格式化和最終驗證。

## 使用方式

在 Cline 中輸入：`/fix-linting.md`

---

## 執行步驟

### 1. 自動修復可修復的問題 🔧

執行 Ruff 自動修復：

```bash
ruff check . --fix
```

**這個步驟會自動修復**：
- 未使用的導入
- 多餘的空格
- 缺少的換行符
- 簡單的代碼風格問題
- 可自動重構的代碼模式

**報告修復結果**：
```
✅ 自動修復了 X 個問題
```

---

### 2. 格式化代碼 🎨

統一代碼格式：

```bash
ruff format .
```

**這個步驟會格式化**：
- 縮排和空格
- 引號風格
- 行長度
- 代碼排版

**報告格式化結果**：
```
✅ 格式化了 Y 個文件
```

---

### 3. 最終驗證 ✅

確認沒有剩餘問題：

```bash
ruff check .
```

**預期結果**：
- 顯示 `All checks passed!` 或 `Found 0 errors`
- 如果仍有錯誤，進入步驟 4

---

### 4. 處理剩餘問題（如果有）⚠️

如果步驟 3 仍然有錯誤，分析並報告：

```bash
# 獲取詳細錯誤
ruff check . --output-format=concise
```

**分類並報告問題**：

#### 安全問題（必須修復）
```
⚠️ 發現安全相關問題：

文件: src/handler.py:97
問題: E722 - 使用了裸 except，應該指定異常類型
風險: 可能隱藏重要錯誤
建議: 將 `except:` 改為 `except Exception:`

這些問題必須修復才能提交。
```

#### 命名問題（需要評估）
```
ℹ️ 發現命名相關問題：

文件: tests/test.py:65
問題: N806 - 變數名稱不符合規範
建議: 重新命名或添加 # noqa: N806（如果有充分理由）
```

#### 代碼簡化建議（可選）
```
💡 發現可選的改進建議：

文件: src/utils.py:42
問題: SIM102 - 可以簡化的條件表達式
建議: 考慮簡化，但不強制
```

---

### 5. 提供總結報告 📊

#### ✅ 所有問題已修復
```
🎉 代碼質量檢查完全通過！

✅ 自動修復：X 個問題
✅ 格式化：Y 個文件
✅ 最終驗證：0 errors

代碼已準備好提交。

建議的 git 操作：
git add .
git commit -m "style: fix linting issues"
git push
```

#### ⚠️ 仍有需要手動處理的問題
```
⚠️ 自動修復完成，但仍有 Z 個問題需要手動處理：

[列出問題清單]

建議：
1. 優先修復安全相關問題
2. 評估命名問題是否需要修復
3. 可選擇性地處理簡化建議

需要我幫助修復這些問題嗎？
```

## 注意事項

### 自動修復的限制
- 不是所有問題都能自動修復
- 安全問題需要人工審查
- 邏輯問題需要理解上下文

### 不要過度依賴
- 自動修復只是第一步
- 仍需要人工審查代碼
- 測試仍然是必須的

### 什麼時候不要使用
- 大規模重構時（應該逐步修復並測試）
- 不確定自動修復是否正確時
- 代碼邏輯複雜時（可能改壞）

## 相關命令

### 只檢查不修復
```bash
ruff check .
```

### 指定特定文件
```bash
ruff check path/to/file.py --fix
```

### 查看所有規則
```bash
ruff linter
```

### 忽略特定規則（謹慎使用）
```python
# 在代碼中添加（需要充分理由）
result = eval(expr)  # noqa: S307 - 已驗證輸入安全性
```

## 快速參考

```bash
ruff check . --fix && ruff format . && ruff check .
```
