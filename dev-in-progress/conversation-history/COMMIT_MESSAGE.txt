Implementation:
- DynamoDB schema with PK (conversation_id) + SK (timestamp)
- TTL support for soft delete (30-day recovery period)
- PITR enabled for data protection
- Dual-write architecture:
  * User messages → DynamoDB (before AI processing)
  * AI processing → Bedrock Memory Service
  * AI responses → DynamoDB (after processing)
- Group conversation support:
  * Shared conversation_id per group
  * Tracks sender_id and sender_name
  * AI loads group context (last 30 messages)
  * Format: [Alice] content
- ConversationService with CRUD operations:
  * save_message()
  * get_messages() with pagination
  * delete_conversation() (soft/hard)
  * restore_conversation()
  * format_messages_for_ai()
- Lambda Layer for code sharing across functions
- Connection pooling optimization (10 connections)
- Automatic retry (3 attempts)
- Error tolerance (storage failures don't block processing)

conversation_id Formats:
- Telegram private: tg:{user_id}
- Telegram group: tg:group:{group_id}
- Web logged-in: web:{user_id}
- Unified (Phase 2): unified:{uuid}
